## English

### 1. What This Is (and Is Not)

This is a **pilot prototype** that explores one idea: a short, user-controlled buffer when someone hesitates before sending a message. It is not a standard, not a validated measurement, and not a clinical tool.

**Correction notice (v0.1.1):** The v0.1.0 README described the demo numbers as "real captured digital exhaust". That was wrong. The demo data is **simulated** with `sleep()` in `typing_demo.py`. There is no real key hook yet, and no real user has been measured.

### 2. Simulated Demo Data (2026-10-27)

Four pauses were generated by the demo script, not observed from a person:

```json
{
  "meta": { "version": "v0.1.1-pilot", "data": "simulated" },
  "typing_pauses_ms": [1035, 1658, 2168, 5213],
  "deletion_count": 4,
  "anxiety_score_heuristic": 59
}
```

- 5213 ms is a number the script produced. It is not a human threshold, and it is not "the 5.2s standard".
- Because the data is simulated, it says nothing about IME candidate selection, hesitation, or anxiety in real typing.

### 3. The Heuristic Score (not clinical)

```
anxiety_score_heuristic = clamp(0.6 * sqrt(longest_pause_ms) + 0.4 * (deletion_count * 10), 0, 100)
```

Worked example: sqrt(5213) = 72.2, so 0.6 x 72.2 = 43.3; 0.4 x (4 x 10) = 16; total 59.3, which the code truncates to **59**.

This is an arbitrary pilot formula. It has no clinical validation, no false-positive rate, and unknown error. Details and limits: [`docs/anxiety_score.md`](docs/anxiety_score.md).

### 4. Design Commitments (user-owned buffer, not surveillance)

These are the rules the project is built to follow. They are design requirements; the real key hook that would need to obey them is **not implemented yet**.

- **On-device only:** pause and deletion data stay on the device and are never uploaded.
- **Opt-in:** the feature is OFF by default.
- **No deleted content:** only the count and timing of deletions are stored, not what was deleted, unless the user explicitly opts into content logging.
- **Purgeable:** one action clears the local buffer.
- If these cannot be guaranteed, the feature does not ship.

How this is checked: `tests/test_no_network.py` (run in CI) fails if `core/` imports network libraries (for example `requests`, `httpx`, `socket`). A pass means no known network imports in `core/`. It is a static import check, not a security audit, and it cannot prove that no network call is ever possible.

### 5. Scope

One scenario only: **pre-send hesitation in messaging ("Should I send this?")**.

Other domains (defense, drones, space, mental-health detection, and so on) are speculative ideas listed in [`docs/future_research_ideas.md`](docs/future_research_ideas.md). They are not validated and not supported use cases. Do not use this project for any critical or diagnostic decision.

### 6. Architecture

- `core/` - only `core/anxiety.py` is the on-device proof (import math only, no network). See [`core/anxiety.py`](core/anxiety.py).
- `typing_demo.py` - local demo with simulated pauses. **This is the only file customers should run: `python typing_demo.py`**
- `docs/` - methodology, limitations, future ideas. Reproducible calc: [`docs/anxiety_score.md`](docs/anxiety_score.md)

Customers should run `typing_demo.py` and use `core/anxiety.py`.

### 4. 設計承諾（使用者擁有的緩衝區，不是監控）

這是專案要遵守的規則，屬於設計要求；需要遵守它們的真實按鍵偵測**尚未實作**。
